# Как добавлять материалы на сайт

Инструкция для преподавателя. Программировать не нужно, ставить ничего на компьютер
не нужно — всё делается через сайт GitHub в браузере.

**Сайт:** https://sharipovaka.github.io/fs1/
**Репозиторий (где лежат файлы):** https://github.com/sharipovaka/fs1

> Техническое описание проекта — в [docs/TECHNICAL.md](docs/TECHNICAL.md).
> Оно нужно только тем, кто правит код.

---

## Главное правило

Сайт собирается из папок. **Куда положили файл — там он и появится.**

```
public/files/
│
├── disciplines/              ← ДИСЦИПЛИНЫ
│   ├── calculus/             ← папка одной дисциплины (матанализ)
│   │   ├── plans/            ← блок «Планы»
│   │   ├── notes/            ← блок «Конспекты»
│   │   ├── library/          ← блок «Учебники и методички»
│   │   ├── templates/        ← блок «Шаблоны»
│   │   └── tasks/            ← блок «Задания»
│   ├── linear-algebra/       ← линейная алгебра
│   ├── discrete-math/        ← дискретная математика
│   ├── teorver/              ← теория вероятностей
│   └── common/               ← общие материалы для всех дисциплин
│
├── activities/               ← АКТИВНОСТИ
│   ├── practice/  spring/  seminars/  reports/  conferences/
│
└── about/
    └── history/              ← История кафедры
```

Пустые блоки на сайте не показываются. Если в `calculus/templates/` ничего нет,
блока «Шаблоны» на странице матанализа просто не будет.

После загрузки файла сайт **пересобирается сам**: подождите 2–4 минуты и обновите
страницу. Ход сборки виден на вкладке **Actions** в репозитории.

## Задача 1. Добавить файл в существующую дисциплину

Например, условия нового типового расчёта по линейной алгебре.

1. Откройте https://github.com/sharipovaka/fs1
2. Пройдите по папкам: `public` → `files` → `disciplines` → `linear-algebra` → `tasks`
3. Нажмите **Add file → Upload files**
4. Перетащите файл в окно
5. Внизу нажмите зелёную кнопку **Commit changes**

Через 2–4 минуты файл на сайте.

---

## Задача 2. Как называть файлы

Имя файла определяет, как материал подпишется на сайте. Это единственное,
что стоит запомнить.

### Начало имени — что за работа

| Пишем в начале | Получится на сайте |
| --- | --- |
| `tr-01-…` | Типовой расчёт № 1 |
| `dz-02-…` | Домашнее задание № 2 |
| `kr-01-…` | Контрольная работа № 1 |
| `lab-03-…` | Лабораторная работа № 3 |
| `rgr-01-…` | Расчётно-графическая работа № 1 |
| `lecture-05-…` | Лекция 5 |

### Конец имени — что это за файл

| Пишем в конце | Подпись на сайте |
| --- | --- |
| `…-usloviya` | Условия задач |
| `…-varianty` | Данные вариантов |
| `…-otvety` | Ответы |
| `…-reshenie` | Пример решения |
| `…-samoproverka` | Материалы для самопроверки |
| `…-metodichka` | Методические указания |
| `…-konspekt` | Конспект |

**Файлы с одинаковым началом склеиваются в одну карточку.** Положили
`tr-03-usloviya.tex` и `tr-03-varianty.csv` — на сайте появится одна работа
«Типовой расчёт № 3» с двумя файлами внутри.

Файл с именем не по правилам не потеряется — он станет отдельной карточкой,
подписанной своим именем.

## Задача 3. Добавить описание к работе

Описание, срок сдачи и название задаются файлом **`_meta.json`**, который лежит
в той же папке. Он необязателен: без него работа всё равно появится.

Чтобы его создать или изменить:

1. Зайдите в папку, например `public/files/linear-algebra/tasks/`
2. Если файла `_meta.json` нет — **Add file → Create new file**, имя `_meta.json`
3. Если есть — нажмите на него, затем на карандаш ✏️
4. Впишите текст по образцу ниже и нажмите **Commit changes**

```json
{
  "items": {
    "tr-03": {
      "title": "Кратные интегралы",
      "due": "2026-12-10",
      "deadline": "14-я учебная неделя"
    }
  },
  "files": {
    "tr-03-usloviya.tex": {
      "label": "Условия задач: восемь заданий и критерии оценивания",
      "primary": true
    }
  }
}
```

Что означают поля:

| Поле | Что делает |
| --- | --- |
| `items` → ключ | начало имени файлов работы: `tr-03` |
| `title` | название работы крупными буквами |
| `due` | **дата сдачи** в формате `ГГГГ-ММ-ДД` |
| `deadline` | пояснение рядом с датой, например «14-я учебная неделя» |
| `files` → ключ | полное имя файла |
| `label` | описание файла в карточке |
| `primary` | `true` у главного файла — его кнопка станет синей |

### Дата сдачи считается сама

Достаточно вписать `due`. Метку состояния сайт подставит сам и будет
пересчитывать её каждый день, без вашего участия:

| Сколько осталось | Что увидит студент |
| --- | --- |
| больше 14 дней | зелёная метка «приём открыт» |
| 14 дней и меньше | жёлтая «осталось 9 дней» |
| сегодня | жёлтая «сегодня последний день» |
| срок прошёл | серая «приём закрыт» |

Эта же дата попадает в сводку в начале страницы дисциплины —
в блок «Сроки сдачи». Работа с самым близким сроком показывается первой.

Если даты нет, можно по-старому написать `"status"` (`open`, `soon`, `done`)
и `"statusLabel"` с произвольным текстом — так сделано у материалов,
у которых срока не бывает.

> **Важно про кавычки и запятые.** JSON придирчив: все тексты в двойных кавычках,
> между записями запятые, после последней записи запятой быть не должно.
> Если ошиблись — сборка упадёт, а на вкладке Actions появится красный крестик.
> Сайт при этом продолжит работать со старой версией, ничего не сломается.

## Что видит студент в начале страницы дисциплины

Сразу под названием стоит сводка из трёх колонок. Заполнять её отдельно
не нужно — она собирается сама:

| Колонка | Откуда берётся |
| --- | --- |
| **Коротко** — курс, семестр, форма контроля | поля `course`, `semester`, `control` дисциплины в `catalog/site.json` |
| **Что на странице** — блоки со счётчиками файлов | из того, какие папки не пустые |
| **Сроки сдачи** — ближайшая работа и дата | из полей `due` в `_meta.json` |

## Задача 4. Добавить новую дисциплину

Например, «Дифференциальные уравнения».

**Шаг 1. Создать папку с файлом.** В GitHub нельзя создать пустую папку, поэтому
папка создаётся вместе с первым файлом:

1. **Add file → Create new file**
2. В строке имени введите путь целиком, через косые черты:
   `public/files/disciplines/diff-equations/tasks/tr-01-usloviya.tex`
   — папки создадутся сами
3. Вставьте содержимое файла и нажмите **Commit changes**

**Шаг 2. Назвать дисциплину.** Откройте `catalog/site.json`, нажмите карандаш ✏️
и допишите в список `disciplines` ещё одну запись:

```json
{
  "id": "diff-equations",
  "title": "Дифференциальные уравнения",
  "short": "Диффуры",
  "icon": "fa-solid fa-infinity",
  "meta": "2 курс · 3 семестр · экзамен",
  "course": "2 курс",
  "semester": "3 семестр",
  "control": "экзамен",
  "description": "Обыкновенные дифференциальные уравнения, устойчивость решений, краевые задачи."
}
```

`id` обязан совпадать с именем папки. Дисциплина появится в меню, на главной
и получит свою страницу — править код не нужно.

## Задача 5. Изменить описание раздела

Тексты, которые видит студент, лежат в двух местах:

| Что меняем | Где |
| --- | --- |
| Описание дисциплины, её курс и семестр | `catalog/site.json`, список `disciplines` |
| Описание блока «Планы», «Учебники и методички» и т. д. | `catalog/site.json`, список `types` |
| Описание раздела «Активности» | `catalog/site.json`, список `activities` |
| Описание конкретной папки | `_meta.json` в этой папке, поле `description` |

Описание из `_meta.json` перекрывает общее описание блока — это удобно, когда
у одной дисциплины «Задания» устроены не так, как у остальных.

## Задача 6. Добавить заседание семинара

Расписание лежит в файле `catalog/seminars.json`. Откройте его, нажмите
карандаш ✏️ и допишите строку в список `sessions`:

```json
{
  "date": "2026-12-16",
  "type": "report",
  "title": "Название доклада",
  "speaker": "кто выступает"
}
```

Дата обязательно в формате `ГГГГ-ММ-ДД` — по ней сайт сам определит,
какое заседание ближайшее, и подсветит его.

Виды доклада (`type`):

| Значение | Как подпишется |
| --- | --- |
| `report` | Научное сообщение |
| `reading` | Разбор статьи |
| `lecture` | Учебная лекция |
| `workshop` | Практикум |
| `other` | Другое |

Аннотации докладов — это файл `annotacii-dokladov.tex` в папке
`public/files/activities/seminars/`. Он показывается на странице целиком,
студенту не нужно ничего скачивать.

## Задача 7. Добавить статью в «Историю кафедры»

Положите PDF в `public/files/about/history/` и подпишите его в `_meta.json`
той же папки:

```json
{
  "items": {
    "nazvanie-fayla": {
      "kind": "Статья",
      "title": "Название статьи",
      "deadline": "Журнал, год, выпуск · автор"
    }
  },
  "files": {
    "nazvanie-fayla.pdf": {
      "label": "О чём статья в одну строку",
      "primary": true
    }
  }
}
```

Статья появится вкладкой на странице и будет читаться прямо на сайте.

## Что происходит с файлами LaTeX

`.tex` компилируется автоматически, и студент получает **готовый PDF** —
ему не нужен TeX на компьютере.

| Файл | Что даёт кнопка «Скачать» |
| --- | --- |
| `tr-01-usloviya.tex` (условия) | PDF, рядом маленькая ссылка на исходник |
| `coursework.tex` (шаблон) | исходник `.tex`, потому что его надо редактировать |

Правило определяется по имени: файлы со словами `usloviya`, `zadanie`, `zadachi`
отдаются как PDF. Если нужно иначе — впишите в `_meta.json` у файла
`"download": "pdf"` или `"download": "source"`.

Файлы `.md`, `.csv` и `.ipynb` тоже можно посмотреть на сайте, не скачивая —
кнопка «Просмотр». У ноутбуков `.ipynb` дополнительно появляется кнопка
**Colab**: студент откроет и запустит их в браузере.

## Если что-то пошло не так

**Файл загрузил, а на сайте его нет.**
Подождите 4 минуты. Затем откройте вкладку **Actions** в репозитории: если
у последней строки красный крестик — сборка не прошла. Чаще всего причина
в опечатке в `_meta.json` или `site.json` (лишняя или пропущенная запятая).

**Сломалось оформление или пропал раздел.**
Ничего страшного: у каждой правки в GitHub есть история. Откройте файл,
нажмите **History**, выберите предыдущую версию и верните её.

**Нужно переименовать или удалить файл.**
Откройте файл на GitHub, нажмите карандаш ✏️ — там же есть корзина 🗑️
для удаления. Имя файла меняется прямо в строке над текстом.

**Не понимаю, куда положить материал.**
Если он относится к одной дисциплине — в её папку. Если нужен всем
(шаблон курсовой, требования к оформлению, справочник) — в `common`.
